# 文件夹整理

## 使用流程

1. 在顶部共享目录栏选择桌面、下载目录或其他文件夹，点击「扫描」完成只读扫描。
2. 打开「文件管理」，进入要整理的目录，点击工具栏「整理」。
3. 默认方案是「桌面与下载整理」，将散文件分到截图、图片、文档、表格、演示文稿、音视频、压缩包、安装包等文件夹。仍可选择按类型、修改年份、修改年月或扩展名整理；修改时间不代表文件创建时间或最近使用时间。
4. 确认源目录和目标目录。默认在源目录下创建分类文件夹，只处理当前层的散文件。已有子文件夹、其中的资料和隐藏文件保持原位。
5. 可添加文件名关键词规则，例如「客户A」→「客户A资料」。规则忽略大小写、按从上到下的顺序匹配，优先于常规分类。
6. 生成预览，逐组查看原路径、目标路径与归类依据。取消勾选可让文件保持原位；支持按组选择、全选可移动文件或全部保持原位。
7. 可修改分类文件夹名称，或为单个文件指定其他分类。同名冲突可选择跳过或自动编号。任何方案修改都必须点击「更新预览」；更新失败时不能执行旧计划。
8. 确认移动后查看成功数与失败明细。点击「完成」返回文件管理，再使用工具栏「撤销」恢复已完成的移动。撤销记录保存在本地，重启后仍可使用。

## 普通文件操作的提交方式

v0.4.1 中，重命名通过回车或勾号提交；复制在系统目录选择框确认目标后执行。普通移动会在选择目标目录后展示文件数量、源目录和目标目录，用户再次点击「确认移动」才执行；取消确认不会发出移动请求。移至废纸篓仍使用独立确认弹窗，规则整理仍须预览后确认。撤销点击即执行，不额外弹窗。

顶部提示为「扫描不改原文件，整理前预览确认」，不承诺所有文件操作都弹窗。扫描索引的占用与清理方式见[本地存储管理](local-storage.md)。以上存储管理和普通移动确认随 v0.4.1 发布，构建状态见发布手册。

## 行为与边界

- 「空间分析」与「文件管理」共用当前扫描目录。目录栏和视图切换固定在内容上方，在两个视图中都可更换目录或重新扫描。切换视图保留文件管理当前子目录和分析页滚动位置。
- 更换目录后立即隐藏旧目录结果，完成新扫描后恢复之前选择的视图。扫描或文件操作进行时，相关目录与扫描控件暂时禁用，防止操作目标发生变化。
- 分类只使用扫描索引中的文件名、类型、扩展名与修改时间。预览仅检查目标元数据以判断冲突，不读取文件内容，也不创建文件夹。
- 截图识别使用图片类型和文件名中的「截图」「截屏」「屏幕快照」、`screenshot` 等关键词，不分析图像内容。
- 分类文件夹的默认名称跟随生成预览时的界面语言；自定义名称保留原文。名称必须是有效的单层文件夹名，不接受路径跳转、路径分隔符、Windows 保留名称或字符。
- 源目录必须位于当前扫描范围内。选择另一个扫描范围之外的源目录时，需要先扫描该目录。
- 「包含子文件夹中的文件」需主动勾选，并会展示项目结构风险提示。启用后会将子目录文件重新归类；隐藏文件仍跳过，目标目录位于源目录内时也会排除其中已有的文件。
- 同名检查同时覆盖磁盘已有项目与本批计划中的重名，计划按稳定路径顺序生成。自动编号保留扩展名；未勾选文件不会移动，预览中的编号可能因此有空号。
- 执行前重新验证索引与磁盘快照。文件变化、目标被占用或权限不足时，相关项失败并保留明细，不覆盖目标。实际移动和撤销使用不能覆盖已有目标的操作；跨磁盘时复制后再删除源文件。
- 整理不会删除重复文件、删除原有文件夹或监控后台变化。撤销恢复文件位置，不移除整理时创建的空分类文件夹；原位置已被占用或文件已变化时，撤销会报告冲突。
- 当前规则与自定义分类仅用于本次向导，尚未保存为可重复使用的模板。语义理解、文档内容分类和云端模型均不在此版本范围内。

文件管理中的图片与 PDF 预览通过本地 IPC 读取当前扫描索引内的文件，单文件上限为 20 MiB；PDF 使用按需加载的本地 PDF.js 渲染首页，完整内容通过默认应用打开。无法读取、加密或不支持的文档会提示使用默认应用，不显示空白查看器。文本预览最多读取前 64 KiB，切换文件后忽略旧请求的结果。

文件管理工具栏左侧放文件操作，右侧放隐藏文件、排序和视图设置；窄窗口中按组换行。列表的目录与文件共用顶部表头；预览在宽窗口中与列表并排，在窄窗口中覆盖右侧区域，可通过关闭按钮收起。

目录选择、扫描启动/取消、整理预览和文件操作在首次点击时立即显示等待状态，关联控件暂时禁用；取消或报错后恢复。目录刷新保留工具栏和原列表，显示正在读取的状态。SQLite 查询、文件读写及系统打开/定位调用在后台线程执行；后端同时只接受一项文件写操作，避免切换页面后重复提交。大文件复制/移动显示等待提示，尚不提供逐字节进度。

重命名通过回车或勾号保存，通过 Esc、叉号或离开编辑框取消。失焦不再自动提交重命名，以免刷新中断对另一个按钮的首次点击。

## 验证

后端整理测试使用独立临时目录，覆盖默认保留子目录与隐藏文件、细分类与语言、关键词优先级、文件去向覆盖、磁盘/批内同名、自动编号、部分选择执行、重复整理、过期文件、预览后目标被占用、日志写入失败回滚，以及持久化撤销和原路径冲突。

```sh
pnpm check
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
```

浏览器回归使用真实 React 组件和独立的模拟 Tauri IPC，不会操作用户文件。需要 Python Playwright、已安装的 Google Chrome 和 Playwright WebKit：

```sh
python3 -m pip install playwright
playwright install webkit
pnpm dev --host 127.0.0.1
# 在另一个终端执行；截图默认输出到系统临时目录的 luma-file-manager-review。
python3 scripts/test-file-manager.py --browser all
```

覆盖整理向导全部步骤、排除文件和自定义分类、修改后更新预览、冲突编号、结果与撤销、取消/确认删除、目录切换、重命名键盘事件、复制/移动参数、隐藏文件、205 文件分页、图片与 PDF 实际渲染、文本请求竞态，以及中英文小窗口布局。共享工作区另覆盖目录栏固定、视图状态保留、更换目录后旧结果隐藏、新扫描恢复原视图和键盘切换。可用 `--workspace-only` 单独执行工作区回归，通过 `--browser-path` 指定 Playwright 浏览器缓存，`--base-url` 指定开发服务地址，`--output` 指定截图目录。

`--layout-only` 会截取中英文、1120×760 和 760×560 窗口中的列表、预览、批量选择、网格及整理弹窗，便于检查组件间距和对齐。

额外的慢请求回归将目录选择、预览、打开文件、扫描启动/取消延迟 800 ms，连续点击三次并核对实际 IPC 请求只发出一次，同时检查按钮 spinner、禁用状态、取消/失败后的恢复，以及重命名草稿不会吞掉对「整理」的首次点击。Rust 测试另验证阻塞任务使用工作线程、错误原样返回，以及并发文件写入被拒绝且失败后能释放互斥锁。

桌面端人工回归应使用测试目录：验证系统权限、原生目录选择、当前层/递归范围、冲突策略、跨磁盘移动、部分失败与重启后撤销。Windows 真机回归仍待 Windows 环境；浏览器中模拟 Tauri IPC 的交互检查不能替代真机文件操作验证。
