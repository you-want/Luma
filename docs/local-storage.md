# 本地存储管理与操作确认

状态：v0.4.1 发布准备（2026-10-27）；实现与回归检查已完成，等待双平台发布流水线。

## 扫描会占用什么

普通扫描不修改原文件，但会在应用数据目录的 `luma.sqlite3` 保存路径、名称、大小、修改时间、搜索索引等元数据。用户主动查重时还会保存本地哈希。数据库不保存原文件副本或内容预览缓存；SQLite 临时日志也会占用磁盘。

这不是零成本缓存：旧实现保存每目录最多三份完整文件索引，没有全局保留限制，也没有主动收缩数据库。v0.4.1 采用以下策略：

- 只保留最近一次成功扫描的完整文件索引；其他成功扫描转换为总量、分类等统计摘要，继续用于历史对比。
- 每个目录最多保留三次扫描记录，全局最多三十次；保留最近一次成功扫描，避免连续失败/取消淘汰最后可用结果。
- 单次扫描相对开始时已用数据库页，新增索引预算为 256 MiB；每批写入在提交前检查，超限回滚当前批次、终止本次扫描并清理其已写入的部分数据。上次成功索引和撤销记录继续保留。
- 为保证失败时仍有可用结果，扫描期间保留旧索引，因此预算不等于应用数据目录的总大小上限。已有超大索引、撤销记录、历史摘要及临时日志也不包含在“单次新增”预算承诺中。旧版单份超大索引不会被强制丢弃，可重新扫描较小目录或主动清理。
- 启动恢复结果前、扫描终态后，在工作线程回收旧索引。删除的全文搜索数据会合并清理；空闲页至少 8 MiB 且达到数据库页数四分之一时自动压缩。手工回收不受该阈值限制。
- 压缩需要临时磁盘空间。失败不会删除数据库文件；空闲页可继续复用，并可稍后手动重试。扫描、原文件写操作与索引清理/压缩共享后端互斥，维护期间不会并发改写。

## 用户入口

顶部「本地存储」展示数据库及临时日志占用、已索引文件数、扫描记录数、可撤销记录数和数据库空闲空间。

- **回收空闲空间**：保留当前有效索引和历史统计，尝试缩小数据库。
- **清理扫描索引**：先说明影响并确认，再删除所有扫描结果和历史统计，回收空闲空间。界面随即回到待扫描状态，原先选中的目录保留。
- 清理不会修改原文件，也不会删除操作日志或撤销数据。重新扫描原目录后，之前属于该目录的撤销记录仍可使用。撤销记录不设静默淘汰期限，避免用户不知情地失去撤销能力；其占用包含在面板总量内。
- 读取、回收、清理均提供等待状态，禁用重复点击。压缩失败与索引清除成功分别反馈；结果不会因压缩失败而继续以旧索引显示。

## 文件操作确认

| 操作 | 提交方式 |
|---|---|
| 重命名 | 回车或勾号保存；失焦取消 |
| 复制 | 在系统目录选择框确认目标后执行 |
| 移动 | 选目标后，核对数量、源目录和目标目录，再确认移动 |
| 移至废纸篓 | 弹窗确认 |
| 规则整理 | 生成清单、调整预览，再点击确认移动 |
| 撤销 | 点击后直接执行 |

界面提示使用「扫描不改原文件，整理前预览确认」，不将“用户主动提交”写成“每项操作都有二次弹窗”。

数据库 schema 升至 v5，新增历史摘要表；已迁移的数据库不能直接交给仅支持 schema v4 的 v0.4.0 客户端读取。开发与迁移回归使用隔离目录，不以降级应用读取新 schema 作为恢复手段。

## 验证

Rust 存储测试使用隔离目录，验证历史摘要与分类对比、清理后重扫仍可撤销真实重命名、容量超限的事务回滚、失败/取消后的旧结果保留、全局历史限制以及压缩前后实际数据库大小。

`python3 scripts/test-file-manager.py --browser all` 覆盖移动确认/取消、参数、等待与单次请求；另覆盖中英文存储面板、回收、清理确认/取消、清理后的工作区重置、撤销记录保留展示、失败重试和 760×560 小窗口。`--workspace-only` 只执行工作区与存储面板回归。浏览器 IPC 模拟不能替代 Windows 真机文件操作验收。
