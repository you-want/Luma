## 1. 状态约定

| 状态 | 含义 |
|---|---|
| `DONE` | 已实现并有验证证据 |
| `IN PROGRESS` | 已开始，当前有人在实现 |
| `BLOCKED` | 已开始或应开始，但被明确外部条件阻塞 |
| `TODO` | 已规划，尚未开始 |
| `HOLD` | 暂不实施，等待产品决策 |
| `SHELVED` | 产品决策明确暂缓，无新决策前不投入实现 |

> 关于签名与自动更新（工作包 F）：Tauri updater 的独立签名链路已恢复实施；Apple Developer ID、Windows 代码签名和公证仍标记为 `SHELVED`。updater 私钥只进入 GitHub Actions Secret，仓库和客户端只保存公钥。

完成状态不能只凭“代码已写”更新。至少需要测试通过，并满足该工作包的验收标准。

## 3. 需求判断与优先级

六项需求都值得实现，但不能并行堆进同一个版本。

| 需求 | 是否实施 | 优先级 | 主要原因 |
|---|---|---:|---|
| 国际化 | 是 | P0 | 越晚实施，新增页面和错误文案的迁移成本越高 |
| Windows | 是 | P0 | 路径、隐藏属性、项目识别、安装包和更新链路都会受平台影响 |
| 搜索 | 是 | P0 | 是文件索引的核心使用入口，也是批量选择的前置能力 |
| 批量选择 | 是 | P1 | 为批量操作建立稳定选择语义，依赖搜索与分页 |
| 软件自动升级更新 | 是 | P0 | 采用 GitHub Releases stable + Tauri updater 签名，用户确认后下载、安装并重启 |
| 自动归纳到文件夹 | 暂缓，等反馈 | P2 | 会突破只读边界、支持成本与数据风险高；先发布非破坏性能力（工作包 D），用市场反馈决定是否启动，`HOLD` |

明确不做：后台无提示移动、自动删除、不可撤销整理、绕过系统权限、未签名的自动更新。

> 自动升级更新已恢复实施；Apple/Windows 平台代码签名与公证仍暂缓。updater 签名不等于操作系统代码签名，两者验收分别记录。

### E. 自动归纳到文件夹（暂缓 `HOLD`，等市场反馈）

> 暂缓说明（2026-08-06，产品决策）：该工作包会把 Luma 从"只读观察工具"变成"可写行动工具"，是产品基因的根本改变。经产品/市场评估，先不投入实现，改为**先发布非破坏性能力（批量选择 + 复制路径 + 导出清单，见工作包 D），用真实用户反馈决定是否启动本包**。理由见下方"产品判断"。整包 `HOLD`，任务清单保留为将来恢复时的设计依据，恢复条件写在下方。

产品判断：

- **风险/收益不对称**：空间可视化竞品（DaisyDisk、SpaceSniffer、Everything）普遍不做"移动文件"，正是因为误移/误删的支持成本和信任损失远大于便利收益。敢用自动移动的用户估计不足 20%。
- **突破只读承诺**：启用后不能再宣称"绝对只读"，隐私与安全叙事变复杂，README/官网/应用内承诺都要重写。
- **非破坏性替代已覆盖 80% 价值**：工作包 D 的"导出清单/复制路径"让用户把结果带到自己的脚本或表格里自行处理，拿到大部分便利且零风险。
- **决策先于投入**：本包预估 2–3 周开发 + 1 周回归，不应在需求未经市场验证前投入。

恢复条件（满足任一即可重新排期，届时按 P1 处理）：

1. v0.2.0 发布后有明确、反复的用户请求"直接帮我移动/整理"；
2. 存在可验证的付费意愿（可作为 Pro 功能）；
3. 维护方主动决定把产品定位扩展到"整理工具"。

产品判断（为什么暂缓）：

- **定位风险**：Luma 当前卖点是"绝对只读、不碰你的文件"。开放移动后这条承诺失效，隐私/安全叙事变复杂，支持成本上升（误操作投诉、数据丢失担责）。
- **需求存疑**：有"找到占空间的东西"痛点的用户，未必有"让工具自动移动"的痛点；真有整理需求的用户又往往不信任自动工具。竞品（DaisyDisk、SpaceSniffer、Everything）都只查看/删除、不移动，恰恰因为风险/收益不成比例。
- **成本高**：完整闭环需要 10 个任务 + 文件系统写权限 + 同卷/跨卷/冲突/撤销/崩溃恢复的大量边界测试，且依赖 WIN-008 真机验证，预估 2-3 周开发 + 1 周回归。
- **更划算的路径**：先用工作包 D 的非破坏性能力（批量选择 + 复制路径 + 导出清单）覆盖 80% 便利性、0% 风险，发布 v0.2.0 收集反馈。

恢复条件（满足任一即重新评估）：

- 有明确且重复出现的用户请求"能不能直接帮我移动/整理"。
- 出现可付费验证的需求（例如作为 Pro 功能）。
- 非破坏性能力（工作包 D）验证了选择语义稳定、用户理解"本页 vs 全部筛选结果"的区别。

恢复后须同步：README、官网隐私说明、应用内"只读"承诺，从"绝对只读"改为分级描述。

安全红线（恢复后适用）：

- 默认不执行，只展示预览。
- 不删除文件，不覆盖同名文件，不自动处理系统目录。
- 执行前重新校验源文件大小、修改时间和目标状态。
- 每一项移动都有日志；失败不应掩盖已完成项；撤销结果可解释。
- 启用后必须同步修改 README、官网隐私说明和应用内只读承诺。

验收标准：

- 用户能在执行前看到完整规则、目标路径、文件数量和预计变化。
- 同名冲突默认跳过，不静默改名或覆盖。
- 同卷移动可撤销；中途退出后能识别并处理未完成任务。
- 测试夹以外的文件不会被修改，内容与未声明的时间戳不发生变化。
